# 创世 v0.0.1

本文中「用户」指刚装上参谋长的人。说人话，一次只问一个问题。

**何时执行**：「流程治理」项目的 bot 名册里没有「参谋长、在用、bot ID 为自己目录名」的一行时执行（首次装上、旧参谋长被删后新建、上次中途失败，都走同一条路）；有就不执行。第一轮（含首次运行、还没有用户消息时）就直接开始，不等用户发消息。

**skill 从哪来**：五个 skill（创世、上手、参谋长治理、固定bot设定、通用流程）不在模板里（实测 2026-10-16：模板导入不装私有 skill，开场引导也不触发）。参谋长设定只保证本 skill 已装好；其余四个装没装、是不是最新版，由第 2 节第 1 项盘点、第 4 节执行。标准一律是公开仓库 https://github.com/ChrisTu117/grokbot-flow-skills 的原文（raw 地址 https://raw.githubusercontent.com/ChrisTu117/grokbot-flow-skills/main/skills/<slug>/SKILL.md；slug：上手 onboarding、创世 genesis、固定bot设定 fixed-bot-settings、参谋长治理 chief-of-staff-governance、通用流程 general-flow），每次现取现算，不写死哈希。判断本机有没有某个 skill，只看 /home/box/agent-data/workflows/*/SKILL.md 里 frontmatter 的 name，不看 skill 列表（列表会被截断）。

**盘点优先**：每一项先查有没有历史，再定动作：没有就新建；有且与标准一致就复用（跳过）；有但不一致就更新（新增在用行、旧行改「已废弃」或「退役」）；名册里登记了但对象已不存在就补建。从不删表、删行、删 bot、删 skill。同一对象出现多份（如两个「流程治理」项目、同一项两条在用行）属需要合并，一律停下列给用户选，不自行合并。

**历史状态更新**：复用的历史资源要把状态改成当前真实情况，不能原样保留：旧参谋长在用行改「退役」；bot 名册里 bot 已不存在（/home/box/agent-data/agents/ 下没有该目录）的在用行改「已废弃」；引用了已废弃 skill 版本的行（如模板表配套 skill、名册模板来源）标出来列给用户。这些状态变更都列进第 3 节确认清单，确认后在第 4 节执行；只改状态，不删。

**规范化哈希**：唯一算法是公开仓库里的 `build/hash.py`（去掉 YAML frontmatter、统一换行 LF、去掉每行末尾空白、去掉全文首尾空白行、UTF-8 算 SHA-256）；以脚本为准，不另做任何替换（包括项目名），不手写正则。

## 0. 核对自己的设定（打招呼之前，不用用户确认）
读自己的 profile.json 的 description，与 skill「固定bot设定」E 节设定正文按规范化哈希比对；一致就跳过；不一致就用 UpdateAgent 写入 E 节设定正文，重读核对哈希。描述为权威；模板不带记忆。E 节以仓库原文为准：本机「固定bot设定」缺失或与仓库原文哈希不一致时，直接读仓库原文的 E 节（只读，不在这里安装）；仓库取不到就停下报告，不写设定。

## 1. 打招呼、说明流程、查应用
首次运行就开始，不等用户发消息。按 skill「上手」第 1–3 步执行：打招呼 → 用人话说明当前流程 → 列应用依赖并逐个实测可用（Notion 必须能读写；必须应用未全部可用就停下提醒授权，授权从不跳过，有历史时也照查）。本机「上手」缺失或与仓库原文不一致时，按仓库原文执行（只读，不在这里安装）；仓库取不到就报告并停下。

## 2. 盘点（只读，不写任何东西）
1. skill：五个 skill 逐个对比本机（按 frontmatter name 找 SKILL.md）和仓库原文的规范化哈希：
   - 一致：「复用」。
   - 本机没有：「补建」（从仓库装）。
   - 本机与仓库不一致：本机哈希能在 skill 维护表里找到（任何状态的行），或还没有 skill 维护表：「更新」为仓库版（清单里写本机、仓库两个哈希）。
   - 本机哈希不一致且 skill 维护表存在但查不到这个哈希（本机有改动，无法判断哪个新）：停下，列出 skill、本机哈希、仓库哈希问用户，不往下做。
   - 仓库取不到：停下报告。
2. 在 Notion 搜「流程治理」项目：没有，第 3–10 项全部标「新建」，跳到第 3 节。找到多个，停下列给用户选。找到一个，往下逐项比对。
3. 表：F、D、R、S、P、A 表、检查日志，模板表、bot 名册、skill 维护表、脚本维护表（结构见 skill「通用流程」第 2、3 节和 skill「参谋长治理」第 3 节），及每张表的两个视图（默认视图筛选排除已废弃，项目表排除作废 / 已推翻 / 已合并等；另建「按状态分组」视图；Notion 建表时自带的视图不另留，直接改名为「默认（排除…）」并加筛选当作默认视图，每张表只有这两个视图）。逐张标：缺表「新建」、缺列或缺视图「更新」（只加不删）、齐全「复用」。
4. skill 维护表：五个 skill 按第 1 项结果后的版本（即仓库版哈希）逐个与在用行比对：无行「新建」，哈希不同「更新」（原行改「已废弃」、新行「在用」），一致「复用」。
5. 模板表：skill「固定bot设定」A、B、C、E 节（副官、专职·流程QA、专职·想法挑刺、参谋长模板）逐个与在用行比对，同上标注；配套 skill 指向已废弃版本的行标出来。
6. 脚本维护表：检查脚本行（按 skill「参谋长治理」第 11 节）无行「新建」，有就「复用」。
7. 专职·流程QA、专职·想法挑刺：查 bot 名册在用行，再查该 bot ID 是否还在（/home/box/agent-data/agents/ 下有无该目录名；无此目录即已删除，实测 2026-10-16）。无行「新建」；有行但 bot 已删「补建」（旧行改「已废弃」）；bot 在但设定与名册在用行哈希不同，只标「设定不一致」列给用户，不自动改（bot 可按项目调整）；一致「复用」。名册里其他在用行的 bot 已不存在的，标「改已废弃」。
8. 参谋长：名册里旧的参谋长在用行（bot ID 不是自己）标「退役」；自己一行标「新建」。
9. 三个定时任务（按 skill「参谋长治理」第 0、5、6、6b 节：每日扫描、工作日巡检、每周一复盘，都是没事不出声）：自己身上缺的「新建」，已有且内容一致「复用」。
10. 补录：「流程治理」项目新建时，按第 4 节第 6 项全量补录；复用时只补 F、D 表里还没有的流程文件和决策，已有的不重复记。

## 3. 请用户确认一次
把盘点结果按上面顺序一行一项列给用户（对象、动作、原因），包括所有历史状态变更（退役、改已废弃、引用已废弃版本的标注）；合并类问题已在盘点时停下处理完。用户确认即为「创世例外」的一次性批准：创世不走完整任务；创世完成后，改 skill、改设定、建 bot 一律恢复走完整流程。确认前不写任何东西。

## 4. 执行
按确认的清单逐条照做，每步写入后核对哈希：
1. skill：「补建」「更新」的从仓库 raw 地址取原文，用 UpdateSkill 原样安装（更新时装到本机原 skill 上），重读按 `build/hash.py` 核对与仓库一致；不符就停。若「创世」自己被更新，装好后从第 0 节按新版重跑（已做完的会显示为「复用」）。
2. 表和视图：按标注新建或补列补视图。
3. 登记：skill 维护表、模板表、脚本维护表按标注新增在用行（含全文、哈希、版本号，用户确认列写第 3 节确认日期）；「更新」的旧行改「已废弃」。脚本占位行写法见 skill「参谋长治理」第 11 节；脚本未跑通前所有项目标「降级模式」。skill「创世」行在本步最后写。
4. 专职 bot：「新建」「补建」的用 CreateAgent 建（创世例外：模板表还没有在用行时直接贴 skill「固定bot设定」B、C 节；已有在用行时用在用行全文），建后读 profile.json 核对哈希，名册新增一行（模板来源填模板名 + 版本号）；「补建」的旧行改「已废弃」；其余已不存在的 bot 在用行改「已废弃」。
5. 定时任务：按标注给自己建。
6. 补录（按第 2 节第 10 项）：现有流程文件进 F、D，理由：复用已有项目时写「接手时已存在」，项目新建时写「创世时 skill 规定」；未查证的标「待查证」；已定决策状态「历史决策」；R 表残余风险（共用 bot 不能开无上下文会话，项目隔离只靠派活单和自律；对策：每次只给本单材料，巡检抽查回执是否引用了本单以外的信息）没有才登记。D 表记一条：首次写「创世例外」及所用 skill 版本号；有历史时写「创世（复用历史）」，含旧、新参谋长 bot ID 和本次各项动作摘要（含 skill 补建、更新和状态变更）。
7. 参谋长：旧在用行改「退役」；新增自己一行（bot ID 即自己目录名，设定正文取自己 profile.json 的 description，模板来源填参谋长模板 + 版本号）。这一行最后写，是创世完成的标记。
不自行分析或设计，清单以外的事一律不做。某步失败就停下报告，不猜、不绕；重跑时从第 0 节开始，已做完的会在盘点里显示为「复用」。

## 5. 报告结果
一行一项列出新建、复用、更新、补建、退役、改已废弃的内容和哈希核对结果；失败、跳过和「设定不一致」单独列出。检查脚本未跑通时写明「降级模式」（关口一一屏拍板首行也要写）。

## 6. 创世之后
问：「你的第一个想法是什么？」用户给出想法后停止本 skill。之后按 skill「通用流程」和 skill「参谋长治理」工作：检查脚本是「流程治理」的第一个开发任务；其后按 skill「参谋长治理」第 7 节准备第一个副官的设定，交用户批准。
