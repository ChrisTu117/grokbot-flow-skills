# 创世

本文中「用户」指刚装上参谋长的人。说人话，一次只问一个问题。

**何时执行**：「流程治理」项目的 bot 名册里没有「参谋长、在用、bot ID 为自己目录名」的一行时执行（首次装上、旧参谋长被删后新建、上次中途失败，都走同一条路）；有就不执行。第一轮（含首次运行、还没有用户消息时）就直接开始，不等用户发消息。

**标准从哪来**：一律是本机克隆 `/home/box/flow-repo` 当前 tag 里的文件：skill 在 `skills/<slug>/SKILL.md`（上手 onboarding、创世 genesis、参谋长治理 chief-of-staff-governance、通用流程 general-flow），bot 模板在 `templates/`，脚本在 `scripts/check.py`，哈希算法在 `build/hash.py`。第 1b 节之前克隆的是公开仓库 https://github.com/ChrisTu117/grokbot-flow-skills（本机还没有克隆时，第 0 节先克隆并切到最新 tag），第 1b 节之后换成本项目仓库。克隆没有任何 tag 就停下报告。skill 不在模板里（实测 2026-10-16：模板导入不装私有 skill，开场引导也不触发），参谋长设定只保证本 skill 已装好，其余三个由第 2 节盘点、第 4 节安装。判断本机有没有某个 skill，只看 /home/box/agent-data/workflows/*/SKILL.md 里 frontmatter 的 name，不看 skill 列表（列表会被截断）；同一 name 有多份 SKILL.md 属需要合并，停下列给用户选。

**盘点优先**：每一项先查有没有历史，再定动作：没有就新建；有且与标准一致就复用（跳过）；有但不一致就更新；名册里登记了但对象已不存在就补建。从不删表、删行、删 bot、删 skill。同一对象出现多份（如两个「流程治理」项目、同一 bot ID 两行没废弃）属需要合并，一律停下列给用户选，不自行合并。

**历史状态更新**：复用的历史资源要把状态改成当前真实情况：名册里旧参谋长的行改「退役」；bot 已不存在（/home/box/agent-data/agents/ 下没有该目录）的行改「已废弃」。这些都列进第 3 节确认清单，确认后在第 4 节执行；只改状态，不删。

**规范化哈希**：一律用克隆里的 `build/hash.py` 算，以脚本为准，不手写正则；算法说明只在 skill「参谋长治理」第 5 节。

## 0. 核对自己的设定（打招呼之前，不用用户确认）
本机没有 `/home/box/flow-repo` 时，先把公开仓库克隆到这里并切到最新 tag（第 3 节确认前写操作白名单第 ③ 项）。读自己的 profile.json 的 description，与克隆里的 `templates/chief-of-staff.md` 按规范化哈希比对；一致就跳过；不一致就用 UpdateAgent 写入这个文件的内容（白名单第 ① 项），重读核对哈希。描述为权威；模板不带记忆。克隆取不到就停下报告，不写设定。

## 1. 打招呼、说明流程、查应用
首次运行就开始，不等用户发消息。按克隆里的 skill「上手」原文执行第 1–3 步：打招呼 → 用人话说明当前流程 → 列应用依赖并逐个实测可用（Notion 实测能读；写权限不在第 3 节确认前测试，第 4 节第一次写入时读回核对，写不进就停；必须应用未全部可用就停下提醒授权，授权从不跳过，有历史时也照查）。

## 1b. 确定本项目仓库
1. 先在 Notion 搜「流程治理」项目：找到多个，按第 2 节第 2 项停下让用户选，选定后再往下。选定（或唯一）的「流程治理」项目页首行有「项目仓库：〈地址〉」，且能从中取到四个 skill、`templates/`、`scripts/check.py`、`build/hash.py`，并且至少有一个 tag：用它，标「复用」。
2. 没有登记（含还没有「流程治理」项目）：问用户「用你自己账号下已有的仓库（给地址），还是我帮你从公开仓库复制一份」。都要用户的 GitHub 账号，并在 bot 电脑命令行登录授权（用户本人完成，授权从不跳过）。帮建：用户同意后在其账号下 fork 公开仓库，或新建仓库并原样推入公开仓库的全部提交和 tag；这是第 3 节确认前写操作白名单第 ② 项，只在用户对这个问题明确回答同意后做；这个同意只覆盖 fork 或新建仓库，不覆盖写项目页、记 D 等其他写入。
3. 核对：上面这些文件都在、至少有一个 tag；新建的再核对它最新 tag 的提交号与公开仓库同名 tag 一致，一致才用。取不到或不符就停下报告。
4. 把 `/home/box/flow-repo` 的远端换成本项目仓库，拉取并切到最新 tag（属白名单第 ③ 项）。
5. 列进第 3 节清单（地址、复用或新建、当前 tag），第 4 节第 3 项写进项目页并记一条 D。

## 2. 盘点（只读，不写任何东西）
1. skill：跑 `python3 /home/box/flow-repo/scripts/check.py run --governance --out /workspace/genesis-check.json`（不带导出目录，只做本机对仓库比对，见 skill「参谋长治理」第 11 节），按输出逐个标：
   - 本机等于克隆：「复用」。
   - 本机没有：「补建」（从克隆装）。
   - 本机能对上仓库某个旧 tag：「更新」为克隆版（清单里写从哪个 tag 到哪个 tag）。
   - 本机哪个 tag 都对不上：本机有改动，无法判断哪个新。停下，列出 skill 和两边哈希问用户，不往下做。用户事先说过的「有冲突一律用仓库版」之类泛泛授权，不算对这一项的确认，照样停下问。
   - 脚本跑不通或克隆取不到：停下报告。
2. 在 Notion 搜「流程治理」项目：没有，第 3–8 项全部标「新建」，跳到第 3 节。找到多个，停下列给用户选。找到一个，往下逐项比对。
3. 表：F、D、R、S、P、A 表、检查日志、bot 名册（结构见 skill「通用流程」第 2、3 节和 skill「参谋长治理」第 3 节），及每张数据库的两个视图（检查日志是页面，不建视图；默认视图筛选排除已废弃，项目表排除作废 / 已推翻 / 已合并等；另建「按状态分组」视图；Notion 建表时自带的视图不另留，直接改名为「默认（排除…）」并加筛选当作默认视图，每张表只有这两个视图）。逐张标：缺表「新建」、缺列或缺视图「更新」（只加不删）、齐全「复用」。
4. 检查脚本：直接用克隆里的 `scripts/check.py`，跑 `python3 /home/box/flow-repo/scripts/check.py selftest`；全部通过标「复用」，不通过就停下报告。
5. 专职·流程QA、专职·想法挑刺：查名册里它们的行，再查该 bot ID 是否还在（/home/box/agent-data/agents/ 下有无该目录名；无此目录即已删除，实测 2026-10-16）。无行「新建」；有行但 bot 已删「补建」（旧行改「已废弃」）；bot 在，就按 `build/hash.py` 把它的设定与克隆里 `templates/qa.md` 或 `templates/idea-critic.md` 在各 tag 的版本比：等于当前 tag「复用」，等于旧 tag 标「落后」、哪个都不等标「设定不一致」，这两种只列给用户，不自动改。名册里其他 bot 已不存在的，标「改已废弃」。
6. 参谋长：名册里旧的参谋长行（bot ID 不是自己）标「退役」；自己一行标「新建」。
7. 三个定时任务（按 skill「参谋长治理」第 0、5、6、6b 节：每日扫描、工作日巡检、每周一复盘，都是没事不出声）：自己身上缺的「新建」，已有且内容一致「复用」。
8. 补录：「流程治理」项目新建时，按第 4 节第 6 项全量补录；复用时只补 F、D 表里还没有的流程文件和决策，已有的不重复记。

## 3. 请用户确认一次
把盘点结果按上面顺序一行一项列给用户（对象、动作、原因），包括所有历史状态变更（退役、改已废弃）和「落后」「设定不一致」的标注；合并类问题已在盘点时停下处理完。用户确认即为「创世例外」的一次性批准：创世不走完整任务；创世完成后，改 skill、改模板、改设定、建 bot 一律恢复走完整流程。**确认前写操作白名单**：确认前只允许三项写操作——① 第 0 节用 UpdateAgent 写自己的设定正文；② 第 1b 节在用户明确同意后 fork 或新建仓库；③ 在本机 `/home/box/flow-repo` 克隆、换远端、拉取、切 tag（只在 box 上，外面看不到）。白名单以外一律不写，包括项目页、D 表、任何「待确认」标注和测试页。

## 4. 执行
按确认的清单逐条照做，每步写入后核对：
1. skill：「补建」「更新」的从克隆取原文，用 UpdateSkill 原样安装（更新时装到本机原 skill 上），装完再跑一次第 2 节第 1 项的检查脚本，确认与克隆一致；不符就停。若「创世」自己被更新，装好后从第 0 节按新版重跑（已做完的会显示为「复用」）。
2. 表和视图：按标注新建或补列补视图。
3. 登记：「流程治理」项目页首行写「项目仓库：〈地址〉」，第二行写「流程版本：〈当前 tag〉」。
4. 专职 bot：「新建」「补建」的用 CreateAgent 建，设定正文用克隆里的 `templates/qa.md`、`templates/idea-critic.md`，建后读 profile.json 核对哈希；名册新增一行（所用模板填文件名 + tag）；「补建」的旧行改「已废弃」；其余已不存在的 bot 行改「已废弃」。
5. 定时任务：按标注给自己建。
6. 补录（按第 2 节第 8 项）：现有流程文件进 F、D，理由：复用已有项目时写「接手时已存在」，项目新建时写「创世时 skill 规定」；未查证的标「待查证」；已定决策状态「历史决策」；R 表残余风险（共用 bot 不能开无上下文会话，项目隔离只靠派活单和自律；对策：每次只给本单材料，巡检抽查回执是否引用了本单以外的信息）没有才登记。D 表记一条：首次写「创世例外」及流程版本 tag；有历史时写「创世（复用历史）」，含旧、新参谋长 bot ID 和本次各项动作摘要（含 skill 补建、更新和状态变更）。
7. 参谋长：旧行改「退役」；新增自己一行（bot ID 即自己目录名，所用模板填 `chief-of-staff.md@〈tag〉`）。这一行最后写，是创世完成的标记。
不自行分析或设计，清单以外的事一律不做。某步失败就停下报告，不猜、不绕；重跑时从第 0 节开始，已做完的会在盘点里显示为「复用」。

## 5. 报告结果
一行一项列出新建、复用、更新、补建、退役、改已废弃的内容和核对结果；失败、跳过、「落后」和「设定不一致」单独列出。报告前按 skill「通用流程」第 10 节「检查脚本」跑一次（参谋长带 `--governance`），按其中「结果写回」格式贴进检查日志并附在报告里；脚本跑不通或结果为「降级」时按该节「降级方案」标降级模式。

## 6. 创世之后
问：「你的第一个想法是什么？」用户给出想法后停止本 skill。之后按 skill「通用流程」和 skill「参谋长治理」工作。第一个副官：用克隆里的 `templates/deputy.md` 建（换项目名），用户批准即可建，不走完整任务（见 skill「参谋长治理」第 7.1 节）。
